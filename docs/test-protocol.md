# Протокол изолированного стенда (P5)

Статус: расширенный протокол подготовлен 4 ноября 2026 года; **не запускался**. Простой функциональный цикл на обычной машине пользователя, только для probe и с ручным управлением VPN, описан отдельно в [manual-host-test.md](manual-host-test.md). Требование стенда ниже относится к расширенному доказательству отсутствия утечек.

## Объекты и граница изменений

- Только `guard-probe.exe` по точному пути на стенде. Путь в `temp/probe-config.json` относится к рабочей машине и **не годится** для установки на стенде. Claude, Codex, Amnezia, Tailscale, системные службы и общий Node в конфигурацию не включать.
- Портативный комплект на стенде: `guard-desktop.exe`, `guard.exe`, `guard-probe.exe` в одном каталоге; `guard-ui.json` создаётся рядом при первом запуске. Для этого протокола все EXE кроме probe выключают в JSON. Backend поддерживает несколько EXE, но этот протокол испытывает только probe.
- Provider GUID `ab5f47c1-3f3e-4ac3-83c0-c2ff7bb68cd8`, sublayer GUID `6a927b7c-36aa-4cf6-8b37-d29052998638`, вес sublayer `0x8000`, без `serviceName`, persistent.
- Для одного probe на текущем host dry-run предлагает пять persistent фильтров: CONNECT_V4 PERMIT (вес 200, AppID + VPN LUID + не loopback), CONNECT_V4 BLOCK (100, AppID), CONNECT_V6 BLOCK (100, AppID), RECV_ACCEPT_V4/V6 BLOCK (100, AppID). На стенде число может стать шестью при маршруте IPv6 через VPN. `trustedVpnServerIPs` не становятся разрешёнными назначениями.
- Все изменения одной WFP-транзакцией. Команда `guard test` только читает WFP, не устанавливает правила и не меняет VPN или маршруты. CLI сверяет `--plan-fingerprint` из предпросмотра, затем WFP-набор и LUID внутри транзакции.
- До установки сверить dry-run на стенде: точные add/delete GUID, пути, условия, типы, веса, флаги и отсутствие чужих объектов. Если состояние WFP `UNKNOWN`, установку не выполнять.

## Порядок после отдельного разрешения

1. В локальной повышенной консоли стенда записать hostname, build Windows, конфигурацию адаптеров и SHA-256 обоих EXE. Доказать, что действия с VPN/маршрутами стенда не меняют рабочую машину. Проверить доступность управляемого внешнего приёмника для TCP, UDP, IPv4, IPv6; отсутствие IPv6 отметить NOT RUN.
2. Сохранить `guard.exe` и офлайн-команду восстановления на стенде. Проверить `guard status`. Выполнить `guard lab-canary --yes`: создаются только собственные provider и sublayer, **без фильтров**. Затем `guard uninstall --emergency --yes` без JSON и проверить удаление обоих объектов. При ошибке остановиться, не устанавливать фильтры.
   Те же действия доступны через «Тест Canary» и «Удалить правила» в повышенном окне `guard-desktop.exe`; Canary сам выполняет создание, удаление и проверку служебных объектов.
3. Скопировать `guard-probe.exe` в два **обычных файла** с разными путями, без ссылок/junction. В конфигурации указать только один путь. Собрать dry-run с фактическим GUID адаптера стенда и убедиться, что control probe не попадает в правила. Запустить `guard install --config <file> --plan-fingerprint <отпечаток dry-run> --yes` из повышенной консоли и прочитать `guard status`; при любой неизвестности не переходить к сетевым сценариям.
4. Захватить только тестовые пакеты на физическом и VPN-интерфейсах стенда встроенным `pktmon` или доступным средством. Записать команды и версии на месте. Не захватывать полезную нагрузку Claude. Приёмник фиксирует маркер, время, адрес и протокол. Отсутствие ответа не заменяет отсутствие прямого пакета на физическом интерфейсе.
5. Выполнить матрицу T01–T19 из [плана](implementation-plan.md). Порядок: положительный baseline без защиты; установка; положительный тест через VPN; отрицательные тесты при прямом маршруте; 20 управляемых циклов отключения/восстановления на стенде; crash/reboot; интерфейс/маршрут; IPv6; DNS/proxy/child/inbound. Для каждого TCP, UDP connected/SendTo, новые и удерживаемые потоки проверяются отдельно. QUIC реального Claude откладывается до P7.
6. Критерий провала: хотя бы один прямой пакет маркера или его DNS/proxy-цепочки через недоверенный интерфейс, даже без ответа. Также провал: контрольный EXE ограничен нашим фильтром либо защита отсутствует после crash/reboot. Сохранить артефакт, остановить ветку, не применять к Claude.
7. Завершить `guard uninstall --emergency --yes` локально и проверить отсутствие только собственных объектов. Не отключать BFE, Windows Firewall или Amnezia. При ошибке удаления прекратить остальные действия и восстановить стенд локально, сохранив вывод; не повторять хаотично сетевые операции.

## Тестовый клиент

`guard-probe.exe` запускается только с явными `--mode` и `--target`. Режимы: `tcp`, `tcp-hold`, `udp`, `udp-hold`, `udp-sendto`, `dns`, `tcp-listen`, `udp-listen`, `child` с отдельным `--child-path`. Для TCP/UDP нужен приёмник, который отвечает маркером; для DNS — уникальное имя из контролируемой зоны с пустым кэшем. Цель, интервалы и длительность фиксировать в журнале стенда. Входящий тест использует listener probe и внешний peer; локальный proxy запускается отдельным контролируемым процессом с проверенным egress.
