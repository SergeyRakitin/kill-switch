# Проверки

## Подтверждено на реальной системе

### Правила по точному пути — `guard-probe.exe`, 10 ноября 2026 года

Пользователь подтвердил:

- интерфейс `guard-desktop.exe` проверен, разделы и операции приложения работают;
- правила WFP успешно установлены через приложение, их состояние корректно отображается;
- **«Проверить запись в WFP» пройдена**: создание, удаление и контроль служебных объектов работают;
- функциональный цикл probe пройден: при включённом VPN получены HTTPS-ответы, после выключения VPN новые соединения запрещены, после включения ответы восстановлены;
- тот же цикл проходит с закрытым `guard-desktop.exe`;
- контрольная копия probe по другому пути не ограничивается политикой выбранного EXE;
- после перезагрузки Windows правила сохраняются: без VPN probe заблокирован, после включения VPN доступ восстанавливается.

### Правила по имени EXE — 11 ноября 2026 года

Пользователь проверил правила по имени EXE на своей машине и подтвердил, что они работают. Отсюда следует, что WFP принимает условие сравнения конца пути (`FWP_MATCH_PREFIX`) в выбранном виде — строка UTF-16 с завершающим нулём.

### Почему MSIX-правило не защищает Claude Desktop — 10 ноября 2026 года

Права запущенных процессов прочитаны через `GetPackageFullName` и `GetTokenInformation`:

- все процессы Claude Desktop (главный, renderer, GPU, сетевой и прочие служебные) запущены из одного `Claude.exe` в `WindowsApps\Claude_4.23118.1.0_x64__pzs8sxrjxfjjc\app` и принадлежат этому пакету, но `TokenIsAppContainer = 0`, SID контейнера приложения отсутствует;
- `claude.exe` Claude Code из `%APPDATA%\Claude\claude-code\2.1.321\…` пакета не имеет.

Условие `FWPM_CONDITION_ALE_PACKAGE_ID` по документации Microsoft — SID контейнера приложения, поэтому MSIX-правило с этими процессами не совпадает. Codex Desktop не проверялся: приложение не было запущено.

## Автоматические проверки

Успешны `npm run build`, `go test ./...`, `go vet ./...` и `scripts/build-desktop.ps1 -SkipInstall`. Тесты probe используют локальные серверы и подменённый сетевой транспорт; тесты GUI-сервиса подменяют запуск `guard.exe` и не изменяют системный WFP. Для правил по имени тестами покрыты проверка имени, построение плана, значение условия в UTF-16 с завершающим нулём, сверка установленных фильтров с планом и передача `--file-name` из GUI.

## Не проверено

- Режим MSIX на реальном приложении в песочнице AppContainer.
- Удаление установленной политики и аварийное восстановление отдельно не зафиксированы.
- Захват пакетов на физическом интерфейсе: без него нельзя утверждать, что любые прямые пакеты исключены.
- Уже открытые TCP/UDP-потоки при отключении VPN, UDP без соединения, DNS, IPv6, прокси, дочерние процессы, входящие потоки, аварийный разрыв VPN, завершение процессов, запуск приложений до старта BFE.
- Расширенные испытания для Claude и Codex.

Для таких испытаний у `guard-probe.exe` есть режимы TCP, UDP, DNS и прослушивания портов — описание в [ручной проверке](manual-host-test.md). Провалом считается хотя бы один прямой пакет тестового маркера, его DNS- или прокси-цепочки через недоверенный интерфейс, даже без ответа.

Корректный итог базовой проверки: **«Функциональный цикл VPN, независимость от GUI, изоляция контрольного EXE и сохранение после перезагрузки подтверждены для probe; правила по имени EXE подтверждены пользователем»**.
