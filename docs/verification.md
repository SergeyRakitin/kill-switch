# Проверки сборки 4 ноября 2026 года

## Обновление 5 ноября: Wails

Резервный Win32 GUI `guard-ui.exe`, его исходники и старые сборки удалены; действующий GUI — только `guard-desktop.exe`. Имя `guard-ui.json` сохранено для совместимости действующей конфигурации.

Новый GUI собран в `dist/guard-desktop.exe`. Полный прогон Go-тестов, TypeScript/Vite и `go vet ./...` прошли. Главная и настройки новой сборки визуально проверены. Список адаптеров ограничен тремя категориями из `networkAdapterTypes`; реальный read-only вызов вернул AmneziaVPN, Wi-Fi, TAP-Windows и Tailscale. При обычном запуске `status` и dry-run получили ERROR_ACCESS_DENIED и показали конкретную инструкцию запуска от администратора. Реальные WFP-мутации и ручной цикл VPN по-прежнему не выполнялись. Актуальные результаты: [wails-desktop.md](wails-desktop.md). Все разделы ниже описывают прежние сборки.


## Обновление: редизайн GUI

Новая сборка `dist/guard-ui.exe` и повторный `go test ./...` прошли после редизайна. Добавлены регрессионные тесты отображения состояний. Визуальный запуск не выполнен; WFP и VPN не изменялись. Подробности и актуальный SHA-256 новой GUI-сборки — [gui-redesign.md](gui-redesign.md). Ниже сохранён отчёт предыдущей сборки; его хеш GUI не относится к новой версии.

## Предыдущий результат

Исходники и три EXE собраны для Windows amd64. Код установки правил, мониторинга и логирования существует, но защита на реальном WFP **не подтверждена**. По просьбе пользователя после последних правок приложения не запускались. Финальный макет UI и новый скриншот отложены для отдельной работы.

| Проверка | Результат | Основание |
| --- | --- | --- |
| `go test ./...` | PASS | Все пакеты с тестами прошли. Тесты probe использовали локальный TLS-сервер и локальные TCP/UDP приёмники; fake monitor проверил ответы → ошибки → ответы и остановку. Тесты UI использовали fake runner для задержки и отмены. |
| `go build -trimpath` для guard и guard-probe, `-ldflags '-H windowsgui'` для UI | PASS | Три EXE собраны в `temp/final-build` и скопированы в `dist`. После последней правки probe пересобран отдельно. |
| JSONL logger | PASS для unit-тестов | Проверены UTC `Z`, отдельные файлы, `runId`/`operationId`, финальная запись, ротация, бюджет, fallback и отказ записи без повторных попыток. [Примеры](../temp/final-build/log-examples-utc) сгенерированы тестом `TestExamples`; они **синтетические** и не показывают реальные WFP или сетевые события. |
| `go vet ./...` | PASS | После замены выходных `uintptr` на типизированные указатели и копирования Win32 callback структур из нативной памяти 13 исходных предупреждений устранены. [vet-latest.txt](../temp/final-build/vet-latest.txt) пуст; проверка запущена с обычными настройками и код возврата 0. |
| Проверка указателей `checkptr=2` | PASS для тестов | `go test -gcflags=all=-d=checkptr=2 ./internal/wfp ./cmd/guard-ui`; unit-тесты проверили WFP union и чтение/запись callback структуры через `RtlMoveMemory`. |
| Анализ размещения WFP объектов компилятором | Частично | [escape-analysis-latest.txt](../temp/final-build/escape-analysis-latest.txt) показывает heap для выходных указателей, filter и вложенных `weight`/`luid`. В коде вложенные адреса дополнительно удерживаются `runtime.Pinner`. Это не заменяет испытание native WFP API. |
| Сохранность пользовательского JSON | PASS для сборки | `dist/guard-ui.json` не перезаписывался при сборке и копировании; его SHA-256 до и после копирования совпал. Unit-тесты миграции сохраняют непустые пути, GUID и пользовательские записи. |
| Финальная визуальная проверка UI и скриншот | NOT RUN | Был предварительный осмотр старой компоновки, после которого код окна менялся. Пользователь попросил продолжать без запуска и отложил финальный UI для другого макета. |
| Реальные WFP add/delete/commit, Canary, аварийное удаление | NOT RUN | Правила на рабочей машине агент не применял. Старый read-only Open/Close вернул `0x00000005`; после последних правок повторного вызова не было. |
| Ручной цикл с выключением и включением VPN, внешний HTTPS, анализ пакетов | NOT RUN | VPN управляет пользователь. Локальные тесты probe не доказывают доступ через VPN и отсутствие прямых пакетов. |
| Stdout JSON при отказе журнала, восстановление WFP при отказе журнала, child/hold/listener на реальной сети | NOT RUN | Разделение stdout/stderr и невлияние журнала на исход операции реализованы в коде; сквозного запуска этих сценариев не было. |

Для `go test` в этой ограниченной среде переменные `TEMP` и `TMP` указывали на `temp/go-test-tmp` внутри проекта: системный временный каталог не позволял тестам создавать файлы. `go vet` выполнялся без подавления предупреждений. В Win32 callback `LPARAM` остаётся числовым адресом; для сообщений с указателем на структуру данные копируются через документированную системную функцию [RtlMoveMemory](https://learn.microsoft.com/en-us/windows/win32/devnotes/rtlmovememory). Нового модуля или UI framework нет.

## Практический предел

`go vet` и `checkptr` теперь проходят, но до live-проверки нельзя утверждать, что все структуры и условия корректно принимаются реальным WFP. Ошибка старого Canary `0x8032001C` не воспроизведена и не доказана исправленной. Успешный ручной цикл из [инструкции](manual-host-test.md) будет наблюдением доступности probe; доказательство отсутствия утечек требует отдельного протокола.
