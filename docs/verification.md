# Проверки

## Подтверждено на реальной системе

10 ноября 2026 года пользователь подтвердил:

- интерфейс `guard-desktop.exe` проверен, разделы и операции приложения работают;
- правила WFP успешно установлены через приложение, их состояние корректно отображается;
- **«Проверка записи WFP» пройдена**: создание, удаление и контроль служебных объектов работают;
- функциональный цикл probe пройден: при включённом VPN получены HTTPS-ответы, после выключения VPN новые соединения запрещены, после включения ответы восстановлены;
- тот же цикл проходит с закрытым `guard-desktop.exe`;
- контрольная копия probe по другому пути не ограничивается политикой выбранного EXE;
- после перезагрузки Windows правила сохраняются: без VPN probe заблокирован, после включения VPN доступ восстанавливается.

Базовый функциональный сценарий для `guard-probe.exe` завершён. Он подтверждает наблюдаемое поведение новых HTTPS-соединений выбранного EXE и постоянство правил, но не заменяет расширенную проверку отсутствия сетевых утечек. Удаление установленной политики и аварийное восстановление отдельно не зафиксированы.

## Автоматические проверки

Зафиксированы успешные `npm run build`, `go test ./...`, `go vet ./...` и `scripts/build-desktop.ps1 -SkipInstall`. Тесты probe используют локальные серверы и fake transport; тесты GUI-сервиса используют fake runner и не изменяют системный WFP.

## Расширенные проверки

За пределами базового сценария остаются захват пакетов на физическом интерфейсе, удерживаемые TCP/UDP-потоки, DNS, IPv6, прокси, дочерние процессы, входящие потоки, аварийный разрыв VPN и завершение процессов: [протокол](test-protocol.md). Защита Claude/Codex этими испытаниями не проверялась.

Без захвата пакетов нельзя утверждать, что любые прямые пакеты исключены. Корректный итог базовой проверки: **«Функциональный цикл VPN, независимость от GUI, изоляция контрольного EXE и сохранение после перезагрузки подтверждены для probe»**.
