# Ручная проверка на рабочей машине

Проверка выполняется на тестовом клиенте `guard-probe.exe`, а не на реальных приложениях. VPN выключает и включает сам пользователь.

## Подготовка

1. Запустите `guard-desktop.exe` через «Запуск от имени администратора». Это не отключает VPN и не меняет правила.
2. Нажмите «Обновить статус». При `ERROR_ACCESS_DENIED` остановитесь и не применяйте план. Если ошибка сохраняется и под администратором, сохраните текст из раздела «Диагностика».
3. Выберите внешний HTTPS URL, который отвечает до установки правил. Программа не выбирает его сама.

Монитор запускается в PowerShell:

```powershell
& '.\guard-probe.exe' --mode https-monitor --target 'https://ВАША-ЦЕЛЬ/' --count 0 --interval 2s --timeout 5s
```

Каждая попытка открывает новое HTTPS-соединение без прокси из окружения. Монитор показывает переходы «Ответы прекратились» и «Ответы возобновились» и останавливается клавишами `Ctrl+C`. Полученный HTTP-ответ с ошибочным кодом отличается от сетевой ошибки.

## Сценарий 1: правило по точному пути

1. Оставьте включённым только `probe`, остальные записи выключите. В «Что изменится в WFP» проверьте путь probe и GUID интерфейса. Если план удаляет правила других приложений, учтите это до подтверждения.
2. Установите правила и запустите монитор из `dist`. При включённом VPN ответы должны идти.
3. Выключите VPN: появляются ошибки и «Ответы прекратились».
4. Включите VPN: появляется «Ответы возобновились».
5. Если «Состояние» сообщает о смене LUID, заново проверьте план и установите правила.

Контрольная копия `guard-probe.exe` по другому пути при выключенном VPN должна продолжать получать ответы: правило по точному пути её не касается.

## Сценарий 2: правило по имени EXE

1. Создайте две копии probe с уникальным именем в разных папках и контрольную копию с другим именем:

```powershell
$lab = 'D:\temp\name-lab'
New-Item -ItemType Directory -Force "$lab\v1", "$lab\v2", "$lab\control" | Out-Null
Copy-Item '.\guard-probe.exe' "$lab\v1\ks-name-probe.exe"
Copy-Item '.\guard-probe.exe' "$lab\v2\ks-name-probe.exe"
Copy-Item '.\guard-probe.exe' "$lab\control\ks-control-probe.exe"
```

2. В панели «EXE по имени (любая папка)» добавьте `ks-name-probe.exe` и установите правила. В плане должна быть строка «ks-name-probe.exe — в любой папке».
3. При включённом VPN запустите монитор для каждой из трёх копий в отдельном окне PowerShell.
4. Выключите VPN: у обеих копий `ks-name-probe.exe` ответы прекращаются, контрольная копия продолжает получать `status=200`.
5. Включите VPN: обе копии восстанавливаются.

Копию для проверки берите не из `dist`: `dist\guard-probe.exe` попадает ещё и под правило `probe` с точным путём, и по ней не видно, какое правило сработало.

После проверки удалите тестовое имя из списка и установите правила заново.

## Что доказывает результат

Успешный цикл подтверждает наблюдаемое поведение новых соединений: при включённом VPN цель доступна, при выключенном ответы прекращаются, после восстановления возвращаются. Он не доказывает отсутствие отдельных прямых пакетов, работу всех протоколов, отсутствие утечек DNS и поведение уже открытых потоков. Без захвата пакетов в итогах пишется «Функциональный цикл пройден» с фактическими наблюдениями, а не «утечек нет».

Журналы probe и `guard.exe` находятся в `dist\logs` либо в каталоге `logDir` из `guard status`.

## Режимы probe для расширенных испытаний

`guard-probe.exe` запускается только с явными `--mode` и `--target`:

| Режим | Назначение |
| --- | --- |
| `https-monitor` | Повторные HTTPS-запросы к URL, по новому соединению на попытку |
| `tcp`, `tcp-hold` | TCP-маркеры приёмнику; `hold` проверяет уже открытое соединение |
| `udp`, `udp-hold`, `udp-sendto` | UDP через подключённый сокет, удерживаемый поток и отправку без соединения |
| `dns` | Запрос уникального имени из контролируемой зоны |
| `tcp-listen`, `udp-listen` | Входящие соединения от внешнего узла |
| `child` | Запуск дочернего probe по `--child-path` в заданном `--child-mode` |

Для TCP и UDP нужен приёмник, который отвечает маркером. Число попыток, интервал и тайм-аут задаются `--count`, `--interval`, `--timeout`.
