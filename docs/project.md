# Windows VPN Kill Switch

## О проекте

Персональная утилита для Windows 11: выбранные приложения выходят в сеть только через заданный VPN-интерфейс, по умолчанию AmneziaVPN. Остальные программы утилита не ограничивает.

Реализованы графический интерфейс `guard-desktop.exe`, консольный `guard.exe`, тестовый клиент `guard-probe.exe`, файловые журналы и работа с WFP с повторной сверкой плана. Приложение задаётся тремя способами: по имени EXE, по точному пути и по MSIX-пакету. Что подтверждено на реальной системе — в [отчёте проверок](verification.md).

## Задача

Если VPN отключился, сервер перестал отвечать или Windows выбрала другой маршрут, защищаемое приложение должно потерять сетевой доступ. Прямое подключение через Wi-Fi, Ethernet или другой недоверенный интерфейс остаётся запрещённым.

Этот принцип называется **fail-closed**: при отказе сохраняется запрет доступа.

## Компоненты и стек

| Компонент | Реализация |
| --- | --- |
| Операционная система | Windows 11 x64 |
| Язык | Go без CGO; Windows API вызываются напрямую из стандартной библиотеки |
| Сетевые ограничения | Windows Filtering Platform (WFP) — системный механизм фильтрации Windows; собственного драйвера нет |
| Графический интерфейс | `guard-desktop.exe`: Wails v3, React, TypeScript; вызывает `guard.exe` для всех операций с WFP |
| Консоль | `guard.exe`: диагностика, предпросмотр, установка, состояние, удаление правил |
| Тестовый клиент | `guard-probe.exe`: HTTPS-монитор и TCP/UDP/DNS-режимы для проверок |
| Конфигурация | `guard-ui.json` рядом с GUI; для CLI — флаги или отдельный JSON |
| Сборка | `scripts/build-desktop.ps1`; описание в [desktop-документе](wails-desktop.md) |

Фоновой службы нет: правила WFP постоянные и действуют без запущенного окна, в том числе после перезагрузки.

## Как работает защита

1. Пользователь выбирает VPN-интерфейс и приложения.
2. `guard.exe install --dry-run` строит план фильтров, читает текущие собственные объекты WFP и вычисляет отпечаток плана. Предпросмотр ничего не меняет.
3. Пользователь подтверждает план. Установка повторно сверяет отпечаток, набор собственных объектов и LUID VPN-интерфейса.
4. Старые собственные фильтры удаляются и новые добавляются одной транзакцией WFP. При любой ошибке транзакция откатывается целиком, прежние правила остаются.
5. После фиксации состояние читается заново и сравнивается с планом.

Для каждого приложения создаются фильтры на слоях `ALE_AUTH_CONNECT_V4/V6` и `ALE_AUTH_RECV_ACCEPT_V4/V6` в собственном sublayer с весом `0x8000`:

- `PERMIT_SOFT`, вес 200: приложение, next-hop — LUID выбранного VPN, соединение не loopback. Создаётся только для семейства адресов, у которого есть маршрут через VPN;
- `BLOCK`, вес 100: приложение, исходящие соединения IPv4 и IPv6;
- `BLOCK`, вес 100: приложение, входящие потоки IPv4 и IPv6.

Внутри sublayer побеждает фильтр с большим весом. Соединение через VPN совпадает с разрешением, любое другое — только с блокировкой. Если VPN выключен или выбран другой маршрут, разрешение не совпадает и действует запрет.

Защита не зависит от надписи Connected в AmneziaVPN, от проверки публичного IP и от запущенного окна утилиты.

## Режимы указания приложения

Режимы различаются только условием, по которому WFP узнаёт приложение. Набор фильтров у всех одинаковый.

| Режим | `type` в JSON | Флаг CLI | Условие WFP | Сравнение |
| --- | --- | --- | --- | --- |
| По имени EXE | `name` | `--file-name` | `FWPM_CONDITION_ALE_APP_ID` | конец пути равен `\имя.exe` |
| По точному пути | `exe` или не задан | `--app` | `FWPM_CONDITION_ALE_APP_ID` | путь равен целиком |
| По MSIX-пакету | `msix` | `--package-family` | `FWPM_CONDITION_ALE_PACKAGE_ID` | SID контейнера приложения равен |

**Рекомендация:** в первую очередь задавать правило по имени EXE — обычно его достаточно. Для Claude это `claude.exe` и `cowork-svc.exe`. Точный путь — когда нужно ограничить одну копию файла; MSIX — только для приложений в песочнице AppContainer.

### По имени EXE

WFP знает каждое приложение по пути к его файлу и хранит этот путь в нижнем регистре в виде пути устройства, например:

```text
\device\harddiskvolume3\program files\windowsapps\claude_4.23118.1.0_x64__pzs8sxrjxfjjc\app\claude.exe
\device\harddiskvolume3\users\<пользователь>\appdata\roaming\claude\claude-code\2.1.321\d020ce1b5d30\claude.exe
```

Правило сравнивает конец этого пути со строкой `\claude.exe`. Используется сравнение `FWP_MATCH_PREFIX`: по документации Microsoft оно, вопреки имени, проверяет конец значения (поддерживается для `FWP_BYTE_BLOB_TYPE` со строкой). Обратная косая черта в начале требует совпадения всего имени файла: `myclaude.exe` не совпадает.

Реализация:

- `config.ValidFileName` принимает только имя файла `.exe` из печатных ASCII-символов, без папок, масок и символов `<>:"/\|?*`. Ограничение ASCII нужно потому, что WFP приводит путь к нижнему регистру, а для не-ASCII символов приведение в Go и в ядре Windows может разойтись — правило молча перестало бы совпадать;
- `policy.FileNameSuffix` строит строку `\` + имя в нижнем регистре; в плане условие записано как `SUFFIX`;
- `wfp` передаёт значение как строку UTF-16 с завершающим нулём — в том же виде, в каком `FwpmGetAppIdFromFileName0` отдаёт полный путь; тип сравнения 11 (`FWP_MATCH_PREFIX`);
- имя фильтра содержит цель `name:<имя>`; при чтении состояния окончание пути показывается как есть, без хеша.

Покрытие: одно правило `claude.exe` охватывает Claude Desktop (все процессы Electron используют один `Claude.exe`), Claude Code из `%APPDATA%\Claude\claude-code\<версия>\` и CLI из `%USERPROFILE%\.local\bin`. После обновления, которое кладёт новую версию в новый каталог, правила менять не нужно, промежутка без защиты нет.

Ограничения: под правило попадает любой EXE с таким именем — такие программы тоже выходят в сеть только через VPN; переименованный EXE не попадает; дочерние программы с другими именами нужно добавлять отдельно.

### По точному пути

При установке `FwpmGetAppIdFromFileName0` переводит путь в путь устройства конкретного файла. Условие `FWPM_CONDITION_ALE_APP_ID` сравнивается с ним целиком (`FWP_MATCH_EQUAL`), поэтому правило действует только на этот файл. При чтении состояния вместо пути показывается его SHA-256.

Проверка конфигурации требует абсолютный локальный путь к существующему обычному файлу `.exe`, без масок, ссылок и неоднозначных путей.

Ограничения: если обновление кладёт приложение в новый каталог, правило остаётся на старом пути, и новая версия не ограничена, пока правила не установлены заново. Подходит для `guard-probe.exe`, программ с постоянным путём и случаев, когда нужно ограничить одну копию, не затрагивая другие файлы с тем же именем.

### По MSIX-пакету

`DeriveAppContainerSidFromAppContainerName` вычисляет из package family SID контейнера приложения, и правило сравнивает с ним `FWPM_CONDITION_ALE_PACKAGE_ID`. По документации Microsoft это условие — SID AppContainer, изолированной песочницы Windows. Правило не зависит от номера версии в каталоге `WindowsApps`.

Ограничения: правило действует только на процессы внутри AppContainer — классические приложения Microsoft Store (UWP). Обычные приложения в MSIX-упаковке работают вне песочницы, и для WFP идентификатор пакета у них пустой. 10 ноября 2026 года чтением прав запущенных процессов установлено: все процессы Claude Desktop принадлежат пакету `Claude_4.23118.1.0_x64__pzs8sxrjxfjjc`, но работают вне AppContainer (`TokenIsAppContainer = 0`), а `claude.exe` Claude Code пакета не имеет вовсе. MSIX-правило Claude не защищает; для него нужны правила по имени. На реальной системе режим MSIX не проверялся.

## Что настраивает пользователь

- Список приложений: имя EXE, точный путь или package family. Служебная запись `probe` обязательна, остальные записи добавляются, выключаются и удаляются.
- VPN-интерфейс: сохраняется GUID, перед установкой Windows переводит его в LUID.
- Категории адаптеров в списке выбора: AmneziaVPN, физические Wi-Fi/Ethernet, другие VPN.
- Установка и явное удаление правил.

## Команды

| Команда | Что делает |
| --- | --- |
| `guard diagnose [--json]` | Интерфейсы, маршруты и DNS; только чтение |
| `guard packages [--json]` | Установленные MSIX-пакеты через `Get-AppxPackage`; только чтение |
| `guard status` / `guard test` | Собственные объекты WFP; только чтение |
| `guard install --dry-run` | План фильтров с отпечатком; WFP не меняется |
| `guard install --plan-fingerprint … --yes` | Установка просмотренного плана одной транзакцией |
| `guard lab-canary --yes` | Создание собственных provider и sublayer без фильтров для проверки записи |
| `guard disable --yes` | Удаление собственных фильтров |
| `guard uninstall --emergency --yes` | Удаление собственных фильтров, sublayer и provider без конфигурации |

Цели передаются флагами `--file-name`, `--app`, `--package-family` вместе с `--vpn-guid` либо файлом `--config` с полями `fileNames`, `applications`, `packageFamilies`, `vpnInterface`.

## Границы защиты

- Правило действует на процессы, совпавшие с условием. Дочерние программы с другим EXE (git, node для MCP-серверов, системные службы) нужно добавлять отдельно. Общий `node.exe` других проектов не стоит ограничивать ради одного приложения.
- DNS-запросы выполняет системная служба, а не приложение; локальные прокси — отдельные процессы. Широкого разрешения loopback нет.
- Если у VPN нет маршрута IPv6, IPv6 для защищаемых приложений заблокирован целиком.
- После смены LUID VPN-интерфейса разрешение перестаёт совпадать и действует запрет; доступ возвращается после повторной установки правил.
- Поведение уже открытых соединений при отключении VPN, прямые пакеты на физическом интерфейсе и запуск приложений до старта BFE отдельно не проверялись.

## Что не входит

Управление VPN-подключением, собственный VPN-протокол, переключение серверов, защита отдельных вкладок браузера, полноценный firewall для всей системы и журналирование пользовательской активности. Утилита не меняет чужие правила Windows Firewall, не отключает BFE и не трогает настройки AmneziaVPN.

## Правила разработки

- От VPN рабочего компьютера зависят сессии разработки, поэтому разработка его не прерывает: допускаются чтение состояния, сборка, тесты и предпросмотр.
- Тесты не меняют WFP: GUI-сервис проверяется с подменённым запуском `guard.exe`, probe — с локальными серверами.
- Реальную установку правил и выключение VPN выполняет только пользователь. Новый способ сопоставления сначала проверяется на копиях `guard-probe.exe`, затем на реальных приложениях.
