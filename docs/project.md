# Windows VPN Kill Switch

## О проекте

Персональная утилита для Windows 11, которая должна предотвращать прямой выход выбранных приложений в интернет при использовании AmneziaVPN. Встроенные записи probe, Claude и Codex и пользовательские EXE можно включать и выключать по точному пути.

По состоянию на 4 ноября 2026 года реализованы GUI, CLI, непрерывный HTTPS probe, файловые журналы и WFP backend с повторной сверкой плана. Сетевые испытания и реальные WFP-мутации ещё не выполнены; защита Claude и Codex не подтверждена. Текущее состояние см. в [отчёте проверок](verification.md).

## Задача

Если VPN отключился, сервер перестал отвечать или Windows выбрала другой маршрут, защищаемое приложение должно потерять сетевой доступ. Прямое подключение через Wi-Fi, Ethernet или другой недоверенный интерфейс должно оставаться запрещённым.

Этот принцип называется **fail-closed**: при отказе сохраняется запрет доступа. Остальные приложения должны продолжать пользоваться сетью без ограничений со стороны утилиты.

## Среда и стек

| Компонент | Выбор для первой версии |
| --- | --- |
| Операционная система | Windows 11 x64 |
| Язык | Go |
| Сетевые ограничения | Windows Filtering Platform — системный механизм фильтрации Windows |
| Работа с WFP | Узкие прямые вызовы Windows API без новой зависимости |
| Низкоуровневые Windows API | Вызовы из стандартной библиотеки Go; нового модуля нет |
| Интерфейс пользователя | Wails/React `guard-desktop.exe` и консольный `guard.exe` |
| Конфигурация | JSON |
| VPN | Уже установленный AmneziaVPN |
| Сборка | Целевая платформа Windows amd64, без CGO и отдельного C++ toolchain |
| Проверка | Go-тесты, отдельная тестовая программа TCP/UDP, анализ сетевых пакетов |

Текущая реализация использует стандартную библиотеку Go и прямые вызовы системных API, без собственного сетевого драйвера. Протокол и драйвер AmneziaVPN необходимо определить на конкретном компьютере: заранее считать их WireGuard нельзя.

## Принцип работы

1. Пользователь указывает исполняемые файлы, которые нужно защитить, и разрешённый VPN-интерфейс.
2. Утилита проверяет конфигурацию и показывает предполагаемые изменения без их применения.
3. При включении защиты утилита устанавливает собственные правила WFP, связывающие выбранные приложения с разрешённым сетевым путём.
4. Windows применяет эти правила к сетевым операциям приложений. Разрешение должно действовать только для проверенного пути через VPN; остальные пути блокируются.
5. Если VPN недоступен, правило не должно давать приложению переключиться на прямой интернет. После восстановления корректного VPN-пути доступ должен возобновляться.

Это целевая модель. Конкретные слои WFP, приоритеты правил и поведение уже открытых соединений необходимо проверить до признания реализации безопасной. Предварительная схема и вопросы исследования описаны в [архитектурных материалах](architecture.md).

Защита не должна зависеть от надписи Connected в AmneziaVPN, периодического запроса публичного IP или работающего окна утилиты. Требуется сохранение правил после завершения CLI и восстановление активной защиты после перезагрузки Windows. Возможность выполнить это без отдельной службы ещё подлежит проверке.

## Что настраивает пользователь

- Список защищаемых EXE с точными путями.
- Разрешённый интерфейс AmneziaVPN.
- Необязательный список IP VPN-серверов для диагностики, пока не доказан более строгий способ его применения.
- Включение и явное отключение защиты.

Адрес VPN-сервера не является адресом назначения Claude. Его наличие в конфигурации не должно разрешать приложению прямые соединения или подменять проверку сетевого пути.

## Основные команды

Команды прототипа собраны; WFP-мутации и реальное сетевое поведение ещё не проверены.

| Команда | Текущее состояние |
| --- | --- |
| `guard diagnose` | Read-only список интерфейсов, маршрутов и DNS; без полного исследования процессов |
| `guard install --dry-run` | Проверяет JSON и выводит кандидат правил; неизвестное состояние WFP обозначает `UNKNOWN` |
| `guard lab-canary` | Код создания своих provider/sublayer без фильтров; не испытан на WFP |
| `guard install` | Код атомарного обновления выбранных EXE по отпечатку предпросмотра; не испытан на WFP |
| `guard status` | Читает свои WFP-объекты; на host возвращает `unknown` из-за ACL |
| `guard test` | Только безопасное чтение WFP, без сетевых действий |
| `guard disable` | Код удаления своих фильтров с `--yes`; не испытан |
| `guard uninstall --emergency --yes` | Код удаления своих объектов без JSON; не испытан |

## Границы защиты

Правило по пути EXE не означает автоматическую защиту всего дерева процессов. Claude Code может использовать Node.js, дочерние программы и инструменты, создающие собственные соединения. Их нужно исследовать и включить в покрытие отдельно. Общий `node.exe`, используемый другими проектами, нельзя блокировать целиком ради Claude.

DNS-запросы и локальные прокси тоже требуют отдельной проверки: сетевой запрос может выполнять системная служба или другой процесс. По умолчанию не предполагается широкое разрешение localhost. Если без локальной связи приложение не работает, безопасную цепочку соединений нужно обосновать.

IPv4 и IPv6 должны учитываться одновременно. Если VPN не обеспечивает проверенный путь для IPv6, защищаемое приложение не должно выходить через прямой IPv6.

Смена или пересоздание VPN-адаптера и обновление пути приложения могут потребовать обновления правил. Необходимо отдельно доказать, что такие события не создают временного прямого доступа.

## Что не входит в первую версию

Управление VPN-подключением, собственный VPN-протокол, переключение серверов, защита отдельных вкладок Chrome, полноценный firewall для всей системы, GUI на Electron и журналирование пользовательской активности.

Утилита не должна менять чужие правила Windows Firewall, отключать BFE или изменять настройки AmneziaVPN. Возможный минимальный служебный компонент рассматривается только при доказанной необходимости для требований защиты.

## Как определяется готовность

Разработка не должна прерывать VPN и интернет рабочего компьютера: от них зависит сессия Codex. На нём допускаются диагностика чтением, сборка и тесты без изменения системы. Пользователь разрешил простой ручной функциональный цикл на своей машине **только для guard-probe**: он сам управляет VPN, а агент готовит код и не применяет правила к работающей сессии. Для расширенных испытаний отсутствия утечек по-прежнему требуется отдельная согласованная среда. Поддержка Claude/Codex в продукте реализуется наравне с другими EXE; это не означает автоматического применения правил к ним.

Сначала правила проверяются на отдельной тестовой программе, затем — на реальных приложениях. Проверяются отключение и восстановление VPN, открытые и новые TCP/UDP-соединения, IPv4/IPv6, DNS, прокси, изменение маршрутов, завершение утилиты и перезагрузка Windows.

Доказательство — наблюдаемые сетевые пакеты и результаты контролируемых испытаний. Один запрос к сервису определения IP недостаточен. Непроведённые проверки должны быть явно указаны; до закрытия обязательных сценариев программа считается прототипом.
