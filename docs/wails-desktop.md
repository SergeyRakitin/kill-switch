# Wails desktop — 5 ноября 2026

## Запуск и сборка

Единственный GUI: `dist/guard-desktop.exe`. Рядом находятся `guard.exe`, `guard-probe.exe` и действующий конфиг `guard-ui.json`. Резервный Win32 GUI `guard-ui.exe` удалён из проекта и комплекта.

Проверенная среда: Go 1.26.10, Node.js 24.13.0, npm 11.6.2, установленный Microsoft WebView2 156. Wails v3.1.0 закреплён в `go.mod`; версии React, TypeScript, Tailwind CSS, Lucide и Vite зафиксированы в `frontend/package-lock.json`. Новые сетевые драйверы и Wails CLI не устанавливались. Go-модуль теперь требует Go 1.26 из-за Wails.

```powershell
& 'D:\projects\github\kill-switch\scripts\build-desktop.ps1'
```

Скрипт устанавливает зависимости через `npm ci`, собирает React, запускает тесты GUI-сервиса, встраивает Windows manifest и собирает `dist/guard.exe` и `dist/guard-desktop.exe`. CLI собирается вместе с окном, потому что окно вызывает его для диагностики и WFP. Для повторной сборки с уже установленными зависимостями используйте `-SkipInstall`. Пути к Go и windres можно передать параметрами `-GoExe` и `-WindresExe`. Используется уже установленный `D:\projects\github\tools\mingw64\bin\windres.exe`. При сборке правила WFP не меняются.

## Устройство

- `frontend/`: React + TypeScript, Tailwind CSS, Lucide SVG, CSS-карточки и переключатели. Vite-результат встраивается в EXE через `frontend/assets.go`; отдельный веб-сервер и CDN не нужны.
- `cmd/guard-desktop/`: окно Wails, связка с сервисом, файл-диалог, системный трей, single-instance и манифест Per‑Monitor V2. Системные DPI-настройки пользователя не меняются.
- `internal/desktop/`: тонкий GUI-сервис над существующим `internal/ui.Client`. Конфигурация читается и атомарно сохраняется прежними функциями. Общий UI-слой фильтрует адаптеры по `networkAdapterTypes` и добавляет к `ERROR_ACCESS_DENIED` инструкцию запуска от администратора. Backend CLI, сетевые правила и WFP не переписаны; read-only диагностика дополнительно возвращает признак физического адаптера.
- `scripts/build-desktop.ps1`: воспроизводимая сборка. Временные файлы и Go-кэш этой ограниченной среды находятся в `temp/`.

Все шесть разделов функциональны. Главная компактная: одна карточка VPN, реальный список приложений, действия и последние три события. Полные пути, ответы CLI и ошибки доступны в подробностях и диагностике. Есть отдельный просмотр плана, копирование журнала, выбор интерфейса и EXE, добавление/удаление пользовательских записей. Обязательные встроенные записи нельзя удалить; их можно выключить.

## Состояние и подтверждения

Переключатель приложения меняет желаемую конфигурацию; WFP изменяется только отдельным действием. Перед исключением приложения, удалением записи, применением/снятием правил и Canary показывается подтверждение. Go независимо проверяет подтверждение, отпечаток предпросмотра и ревизию конфигурации. Операции сериализованы; `Snapshot` остаётся доступным во время работы.

Состояние защиты берётся из реального `guard status`; неполный JSON отклоняется. Проверка сравнивает отпечатки двух снимков и использует существующий `wfp.Verify`. Приложения считаются проверенными только после совпадения всей политики. Для относительного пути probe используется сопоставление по ID, а не по имени файла. Подключённый VPN сам по себе не подтверждает фильтры или отсутствие утечек.

Во время мутации старый зелёный статус снимается. Закрытие атомарно блокирует новые операции и не разрешается посреди текущей; выход никогда не вызывает удаления фильтров. Второй экземпляр GUI открывает уже существующее окно. Это не блокирует отдельный запуск CLI.

Canary сохранён как лабораторный тест создания и удаления служебных объектов без фильтров. Он не является тестом трафика. Межпроцессная гонка с отдельным CLI между созданием и очисткой остаётся ограничением прежнего механизма; сетевое ядро ради GUI не менялось. Реальные Canary/установка/удаление в этой работе не запускались.

## Проверка и ограничения

- `npm run build`, `go test ./...`, `go vet ./...` и штатный `scripts/build-desktop.ps1 -SkipInstall` — PASS. Два предупреждения Lucide `use client` не мешают клиентской сборке.
- Fake-runner сценарии дополнены проверками категорий адаптеров, сохранения выбранного GUID, миграции JSON и подробного `ERROR_ACCESS_DENIED`. Они не выполняют системные WFP-операции.
- Реальный read-only `diagnose` через новый `guard.exe` вернул четыре разрешённых адаптера: AmneziaVPN, Intel Wi-Fi, TAP-Windows и Tailscale. Служебные адаптеры отфильтрованы.
- Реальные `status` и `install --dry-run` без повышения вернули ожидаемый `ERROR_ACCESS_DENIED`; UI-слой сохранил конкретную причину и добавил инструкцию запуска от администратора. Это не подтверждает успешную работу WFP под администратором.
- Новая сборка запущена без повышения; главная и настройки визуально проверены. Окно затем закрыто штатно. AmneziaVPN после проверок осталась `Up`.
- `dist/guard-ui.json` мигрирован новой сборкой: GUID, пути и переключатели сохранены, добавлены три `networkAdapterTypes`.
- Реальные Canary, install/uninstall, отключение VPN и сетевой цикл probe не запускались. Компактный размер, WebView zoom 125–200%, смена системного DPI и перенос между мониторами не проверялись.
