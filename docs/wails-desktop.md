# Графический интерфейс guard-desktop

## Запуск и сборка

GUI — `dist\guard-desktop.exe`. Рядом лежат `guard.exe`, `guard-probe.exe` и конфигурация `guard-ui.json`, которая создаётся при первом запуске. Для работы с WFP окно запускается от имени администратора.

Сборка проверялась на Go 1.26.10, Node.js 24.13.0, npm 11.6.2 и WebView2 156. Wails v3.1.0 закреплён в `go.mod`; версии React, TypeScript, Tailwind CSS, Lucide и Vite — в `frontend/package-lock.json`. Wails CLI не нужен.

```powershell
.\scripts\build-desktop.ps1
```

Скрипт устанавливает зависимости через `npm ci`, собирает React, запускает тесты GUI-сервиса, встраивает Windows manifest и собирает `dist\guard.exe`, `dist\guard-desktop.exe` и `dist\guard-probe.exe`. С уже установленными зависимостями используйте `-SkipInstall`. Go и windres ищутся в `PATH`, пути к ним можно передать параметрами `-GoExe` и `-WindresExe`. Пока `guard-desktop.exe` запущен, его файл занят и пересобрать его нельзя. Сборка правила WFP не меняет.

## Устройство

- `frontend/`: React + TypeScript, Tailwind CSS, иконки Lucide. Результат Vite встраивается в EXE через `frontend/assets.go`; веб-сервер и CDN не нужны.
- `cmd/guard-desktop/`: окно Wails, связка с сервисом, диалог выбора файла, системный трей, запуск в одном экземпляре и манифест Per-Monitor V2.
- `internal/desktop/`: сервис GUI над `internal/ui.Client`. Все операции с WFP выполняются вызовом `guard.exe`; конфигурация читается и атомарно сохраняется функциями `internal/ui`.
- `scripts/build-desktop.ps1`: воспроизводимая сборка; временные файлы и Go-кэш лежат в `temp/`.

## Разделы

- **Главная**: состояние защиты, сводка (фильтры WFP, VPN-интерфейс, число приложений в установленных фильтрах по видам), три списка приложений, кнопки установки и удаления правил, последние три события. Пока при запуске читаются правила WFP и сетевые адаптеры, вместо страницы показывается плашка «Загрузка…».
- **Настройки**: выбор VPN-интерфейса.
- **Правила WFP**: provider, sublayer и собственные фильтры с условиями; исходный JSON свёрнут отдельно.
- **Диагностика**: ответы `guard.exe`, ошибки, «Что изменится в WFP» и «Проверить запись в WFP».
- **Журнал**: события текущего сеанса; копирование и очистка. Записываются действия пользователя, смена состояния защиты и предупреждения, которые требуют действий: VPN-интерфейс не найден, у VPN нет маршрута IPv4, ошибки `guard.exe`. Обновление статуса без изменений и постоянные пояснения о режимах в журнал не пишутся.
- **О программе**.

`Ctrl+A` выделяет только содержимое текущего раздела.

## Списки приложений

На главной три панели — по одной на режим защиты, в порядке рекомендации; как работает каждый режим, описано в [описании проекта](project.md). У заголовка каждой панели есть значок «?»: при наведении или фокусе с клавиатуры подсказка показывает условие WFP этого режима и набор создаваемых фильтров.

- **EXE по имени (любая папка)** — кнопка «Добавить имя». Окно принимает только имя файла: пустое значение, путь с папкой, маски, не-ASCII символы и имя без `.exe` отклоняются сразу, с текстом ошибки под полем; окно при этом остаётся открытым. Ошибки сервиса, например повтор имени, показываются там же. Окно закрывается только после успешного добавления; Enter в поле работает как кнопка «Добавить».
- **EXE по точному пути** — кнопка «Добавить путь» открывает выбор файла; у записи есть «Выбрать другой EXE». Если файла по пути записи нет, например после обновления, которое перенесло приложение в новый каталог, вместо статуса показывается красный значок «Файл не найден». Пока такая запись включена, «Установить правила» и переключатель на главной недоступны, а под сводкой объяснено, что сделать: удалить или выключить запись либо выбрать EXE заново. Наличие файлов проверяется при каждом обновлении статуса и после изменения списка.
- **Пакеты MSIX (Windows App)** — кнопка «Добавить пакет»: список установленных пакетов из `guard packages` или ручной ввод package family. Окно предупреждает, что правило действует только на приложения в песочнице AppContainer.

У каждой записи есть переключатель защиты и меню: подробности и удаление. Служебный `probe` удалить нельзя.

## Состояние и подтверждения

Переключатель приложения меняет желаемую конфигурацию; WFP изменяется только отдельным действием. Перед исключением приложения, удалением записи, установкой и снятием правил и проверкой записи WFP показывается подтверждение. Go независимо проверяет подтверждение, отпечаток предпросмотра и ревизию конфигурации. Операции выполняются по одной; снимок состояния доступен и во время работы.

Состояние защиты берётся из реального `guard status`; неполный JSON отклоняется. Приложения считаются проверенными только после совпадения всей установленной политики с планом (`wfp.Verify`). Сводка на главной берёт цели из имён собственных фильтров и показывает их число по видам, например «По имени: 5 · По пути: 3 · MSIX: 2»; полный список появляется во всплывающей подсказке при наведении или фокусе с клавиатуры. Предупреждение «Есть изменения, установите новые правила» означает расхождение конфигурации с установленной политикой.

Во время изменения WFP прежний зелёный статус снимается. Закрытие окна не разрешается посреди операции, а выход никогда не удаляет фильтры. Второй экземпляр GUI открывает уже существующее окно; отдельный запуск CLI это не блокирует.

«Проверить запись в WFP» создаёт и удаляет служебные объекты без фильтров. Это не тест трафика; при уже существующих собственных объектах проверка отклоняется.

## Проверки

- `npm run build`, `go test ./...`, `go vet ./...` и `scripts/build-desktop.ps1 -SkipInstall` проходят. Два предупреждения Lucide `use client` не мешают сборке.
- Тесты сервиса подменяют запуск `guard.exe` и не меняют системный WFP.
- Пользователь проверил интерфейс на реальной системе, включая установку правил и окно добавления EXE по имени.

Собранные EXE, пользовательский JSON и журналы не входят в Git.
