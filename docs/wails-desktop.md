# Wails desktop — 5 ноября 2026

## Запуск и сборка

Единственный GUI: `dist/guard-desktop.exe`. Рядом находятся `guard.exe`, `guard-probe.exe` и действующий конфиг `guard-ui.json`. Резервный Win32 GUI `guard-ui.exe` удалён из проекта и комплекта.

Проверенная среда: Go 1.26.10, Node.js 24.13.0, npm 11.6.2, установленный Microsoft WebView2 156. Wails v3.1.0 закреплён в `go.mod`; версии React, TypeScript, Tailwind CSS, Lucide и Vite зафиксированы в `frontend/package-lock.json`. Новые сетевые драйверы и Wails CLI не устанавливались. Go-модуль теперь требует Go 1.26 из-за Wails.

```powershell
& 'D:\projects\github\kill-switch\scripts\build-desktop.ps1'
```

Скрипт устанавливает зависимости через `npm ci`, собирает React, запускает тесты GUI-сервиса, встраивает Windows manifest и собирает `dist/guard.exe`, `dist/guard-desktop.exe` и `dist/guard-probe.exe`. CLI собирается вместе с окном, потому что окно вызывает его для диагностики и WFP; probe нужен для безопасной сетевой проверки. Для повторной сборки с уже установленными зависимостями используйте `-SkipInstall`. Go и windres ищутся в `PATH`, а пути к ним можно передать параметрами `-GoExe` и `-WindresExe`. При сборке правила WFP не меняются.

## Устройство

- `frontend/`: React + TypeScript, Tailwind CSS, Lucide SVG, CSS-карточки и переключатели. Vite-результат встраивается в EXE через `frontend/assets.go`; отдельный веб-сервер и CDN не нужны.
- `cmd/guard-desktop/`: окно Wails, связка с сервисом, файл-диалог, системный трей, single-instance и манифест Per‑Monitor V2. Системные DPI-настройки пользователя не меняются. Запрет захвата окна не устанавливается; контекстное меню WebView включено. Глобальные клавиатурные перехваты не используются.
- `internal/desktop/`: тонкий GUI-сервис над существующим `internal/ui.Client`. Конфигурация читается и атомарно сохраняется прежними функциями. Общий UI-слой фильтрует адаптеры по `networkAdapterTypes` и добавляет к `ERROR_ACCESS_DENIED` инструкцию запуска от администратора. Backend CLI, сетевые правила и WFP не переписаны; read-only диагностика дополнительно возвращает признак физического адаптера.
- `scripts/build-desktop.ps1`: воспроизводимая сборка. Временные файлы и Go-кэш этой ограниченной среды находятся в `temp/`.

Все шесть разделов функциональны. Главная одноколоночная и по умолчанию имеет ширину 860 px: горизонтальная сводка состояния, реальный список приложений, действия и последние три события. Отдельной карточки VPN и проверки записи WFP на главной нет; проверка доступна в диагностике. Полные пути, ответы CLI и ошибки доступны в подробностях и диагностике. Предпросмотр называется «Что изменится в WFP». Подробный статус показан структурированно; исходный JSON свёрнут отдельно. Журнал и диагностику можно копировать кнопкой, а `Ctrl+A` выделяет только содержимое текущего раздела. Есть выбор интерфейса и EXE, добавление/удаление независимых записей. По умолчанию остаётся только служебный probe, который нельзя удалить; Claude CLI/Desktop и Codex добавляются отдельными записями.

## Состояние и подтверждения

Переключатель приложения меняет желаемую конфигурацию; WFP изменяется только отдельным действием. Перед исключением приложения, удалением записи, применением/снятием правил и проверкой записи WFP показывается подтверждение. Go независимо проверяет подтверждение, отпечаток предпросмотра и ревизию конфигурации. Операции сериализованы; `Snapshot` остаётся доступным во время работы.

Состояние защиты берётся из реального `guard status`; неполный JSON отклоняется. Проверка сравнивает отпечатки двух снимков и использует существующий `wfp.Verify`. Приложения считаются проверенными только после совпадения всей политики. Для относительного пути probe используется сопоставление по ID, а не по имени файла. Подключённый VPN сам по себе не подтверждает фильтры или отсутствие утечек. Сводка на главной отдельно показывает пути из установленных фильтров: read-only статус извлекает их из имён собственных фильтров, поэтому список сохраняется при неприменённых изменениях настроек и после перезапуска. Предупреждение «Есть изменения, установите новые правила» относится к расхождению конфигурации с установленной политикой.

Во время мутации старый зелёный статус снимается. Закрытие атомарно блокирует новые операции и не разрешается посреди текущей; выход никогда не вызывает удаления фильтров. Второй экземпляр GUI открывает уже существующее окно. Это не блокирует отдельный запуск CLI.

Кнопка «Проверить запись в WFP» запускает лабораторную проверку создания и удаления служебных объектов без фильтров. Она не является тестом трафика и отклоняется при уже существующих собственных объектах. Межпроцессная гонка с отдельным CLI между созданием и очисткой остаётся ограничением прежнего механизма; сетевое ядро ради GUI не менялось.

## Проверка и ограничения

- `npm run build`, `go test ./...`, `go vet ./...` и штатный `scripts/build-desktop.ps1 -SkipInstall` — PASS. Два предупреждения Lucide `use client` не мешают клиентской сборке.
- Fake-runner сценарии проверяют операции без системных WFP-изменений. Read-only диагностика вернула разрешённые адаптеры и корректно отфильтровала служебные.
- Пользователь проверил интерфейс на реальной системе: разделы и операции приложения работают.
- Пользователь подтвердил успешную установку правил WFP через приложение и корректное отображение их состояния.
- «Проверка записи WFP» пройдена: создание, удаление и контроль служебных объектов работают.
- Функциональный цикл VPN для probe пройден, в том числе с закрытым GUI. Контрольный EXE не ограничен, правила сохраняются после перезагрузки. Удаление установленной политики отдельно не зафиксировано.

Собранные EXE, пользовательский JSON, журналы и снимки проверок не входят в Git. Их хеши в документации не фиксируются, чтобы они не расходились со сборками, содержащими Git-метаданные.
