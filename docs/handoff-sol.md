# Задание для Sol

Историческая передача до ревью 4 ноября 2026 года. Реализация уже начата; текущие решения и статус находятся в [review-2026-11-04.md](review-2026-11-04.md), [manual-host-test.md](manual-host-test.md) и [verification.md](verification.md). Эта записка не задаёт актуальные продуктовые запреты на Claude/Codex и не отменяет разрешённый простой ручной тест только для probe.

Критичное ограничение для агента: не прерывать VPN и интернет рабочего компьютера. Не отключать VPN/адаптеры, не менять маршруты/DNS/proxy, не останавливать сетевые службы и не перезагружать host. Продукт поддерживает Codex как обычный EXE; агент не применяет правила к работающей сессии.

На рабочем компьютере выполняй чтение, сборку, unit-тесты без системных мутаций и dry-run. Реальные WFP-эксперименты и испытания отказов — сначала только на отдельно согласованном изолированном Windows-стенде, не влияющем на host-сеть. Если стенда нет, подготовь код и протокол, отметь сетевые испытания BLOCKED/NOT RUN и не запускай их на host. Не создавай VM или сетевую инфраструктуру без согласования. Подробные границы указаны в начале технического плана.

Прочитай глобальные и локальные AGENTS.md, затем `docs/project.md`, `docs/original-request.txt`, `docs/implementation-plan.md`, `docs/architecture.md`. Основной технический файл для работы — `docs/implementation-plan.md`; эта записка служит только кратким вводным заданием. Документация проекта ведётся в Markdown.

Реализуй минимальный Windows VPN Kill Switch по этапам P0–P7. Сначала read-only диагностика и исследование. Основной язык Go, без CGO и собственного драйвера. Не объявляй гипотезы архитектуры доказанными: правила в разделе 3 — кандидат для стенда. Особенно проверь reauthorization открытых потоков, hard permit, provider/serviceName после reboot, пересоздание LUID, DNS и proxy, дочерние процессы и inbound-originated flows.

Веди `temp/implementation-task.md` с текущим этапом и точкой продолжения. После этапа показывай результат и подходящую проверку. Пока не достигнута граница разрешений, продолжай самостоятельно. Не коммить, не пушь, не устанавливай сторонние программы и драйверы без соответствующего разрешения.

До изменения WFP подготовь dry-run, тестовый клиент, конкретный план системных изменений и рабочее аварийное удаление. Затем получи явное разрешение пользователя на тестовые фильтры на указанном изолированном стенде. Применение к настоящим Claude на host обсуждается отдельно после стенда; намеренный обрыв host VPN исключён из текущего разрешения. Не делай системные изменения скрытыми действиями `guard test`.

Критерий: покрытые приложения не отправляют прямые пакеты через недоверенные интерфейсы во всех обязательных проверенных сценариях, контрольные приложения не ограничены нашей политикой, после crash/reboot защита действует. Пока критичный тест не выполнен, результат — прототип с ограничениями. Если требования без службы/драйвера несовместимы с доказанной защитой, останови небезопасную ветку и предложи минимальную альтернативу с конкретной причиной.

Первое действие: сверить состояние рабочей папки и доступные инструкции, проверить установленные инструменты, начать P1 без изменений сети.
