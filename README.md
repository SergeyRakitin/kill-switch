# VPN Kill Switch для Windows

Портативный прототип на Go ограничивает выбранные EXE правилами Windows Filtering Platform (WFP), привязанными к заданному GUID интерфейса Amnezia VPN. Для probe подтверждены установка правил, функциональный цикл VPN, работа без GUI, изоляция контрольного EXE и сохранение после перезагрузки. Отсутствие любых прямых пакетов этими испытаниями не доказывается.

GUI — **Wails v3 + React + TypeScript + Tailwind CSS + Lucide**. Запускайте `dist/guard-desktop.exe`. Компактная главная с горизонтальной сводкой состояния, шесть разделов и системный трей используют реальные команды Go. Сборка, проверки и ограничения: [Wails desktop](docs/wails-desktop.md).

## Комплект и настройки

`dist/guard-desktop.exe`, `dist/guard.exe`, `dist/guard-probe.exe` лежат рядом с `dist/guard-ui.json`. Окно читает GUID из JSON и не заменяет его автоматически. LUID вычисляется из GUID при построении и применении плана. После переподключения VPN кнопка «Проверить состояние» сравнивает текущий LUID с наблюдаемым в собственных фильтрах и предлагает повторно применить правила при изменении.

Список адаптеров ограничен категориями из поля `networkAdapterTypes`: `amnezia-vpn`, `physical` (физические Wi-Fi/Ethernet) и `other-vpn`. По умолчанию включены все три; служебные WAN Miniport, Wi-Fi Direct, Bluetooth, loopback и виртуальные коммутаторы скрыты. Текущий выбранный GUID остаётся в списке даже при отключении его категории. После ручного изменения JSON перезапустите GUI.

Для чтения и изменения WFP закройте обычное окно и запустите `guard-desktop.exe` от имени администратора. Перезапуск сам не меняет VPN или правила. При `ERROR_ACCESS_DENIED` не повторяйте проверку записи WFP или установку: сначала добейтесь успешного чтения состояния.


По умолчанию присутствует только служебный `probe`; его нельзя удалить. Остальные приложения добавляются через меню или JSON и могут быть удалены. Claude CLI, Claude Desktop и Codex можно добавлять как независимые записи, включая несколько EXE с одинаковыми именами по разным путям. Включённые пути проверяются до изменения WFP. Переключатель сохраняет **желаемую настройку**; действие «Установить правила» обновляет собственные фильтры. Когда все записи выключены, «Установить правила» удаляет собственные фильтры после подтверждения.

Существующий JSON при запуске получает категории адаптеров по умолчанию. Выключенные устаревшие заглушки Claude/Codex с путём `Z` или пустым путём удаляются; реальные пути, GUID и пользовательские записи сохраняются. Сохранение идёт через временный файл в том же каталоге и замену. Если сохранение не удалось, состояние окна не меняется.

## Сборка

Новый GUI (Go 1.26+, Node.js и установленный WebView2):

```powershell
& 'D:\projects\github\kill-switch\scripts\build-desktop.ps1'
```

Отдельная сборка CLI и probe из корня проекта:

```powershell
$env:CGO_ENABLED = '0'
& 'D:\projects\github\tools\go\bin\go.exe' test ./...
& 'D:\projects\github\tools\go\bin\go.exe' build -trimpath -o 'dist\guard.exe' ./cmd/guard
& 'D:\projects\github\tools\go\bin\go.exe' build -trimpath -o 'dist\guard-probe.exe' ./cmd/guard-probe
```

Сборка не устанавливает правила и не меняет VPN.

## Простой ручной тест только для probe

Выберите сами внешний HTTPS URL, который отвечает до установки правил. Не используйте URL с учётными данными или query-параметрами. Откройте PowerShell в каталоге `dist` и запустите непрерывный монитор:

```powershell
& '.\guard-probe.exe' --mode https-monitor --target 'https://ВАША-ЦЕЛЬ/' --count 0 --interval 2s --timeout 5s
```

Убедитесь, что ответы есть. В `guard-ui.json` оставьте включённым только `probe`, а Claude, Codex и пользовательские EXE выключите. Закройте обычное окно, откройте `guard-desktop.exe` от имени администратора и нажмите «Обновить статус». При `ERROR_ACCESS_DENIED` не переходите дальше. Проверьте путь probe и GUID, нажмите «Что изменится в WFP» в диагностике, затем «Установить правила» и проверьте перечисленные в подтверждении EXE, добавляемые и удаляемые фильтры. При включённом VPN ответы должны продолжаться. **Вы сами** выключаете VPN, наблюдаете ошибки и сообщение «Ответы прекратились», затем включаете VPN и наблюдаете новые попытки и возможное «Ответы возобновились». Ошибки и timeout не останавливают монитор. При смене LUID нажмите «Обновить статус» и, если окно указывает на изменение, повторно примените правила после нового предпросмотра. Остановите монитор `Ctrl+C` и нажмите «Удалить правила»; окно перечитает WFP.

Если исходных ответов нет, цикл не готов к оценке. Успешный цикл подтверждает наблюдаемые ответы, их прекращение и восстановление, но не отсутствие прямых пакетов, работу всех протоколов, DNS или открытых потоков. Пользователь дополнительно подтвердил работу без GUI, изоляцию контрольного EXE и сохранение правил после перезагрузки.

## CLI и подтверждение плана

`guard install --dry-run --app 'C:\Путь\a.exe' --app 'C:\Путь\b.exe' --vpn-guid '{GUID}'` выдаёт JSON с `fingerprint`, списком `add` и `delete` и исходным состоянием WFP. Для реального `install` нужны тот же набор аргументов, `--plan-fingerprint` из просмотренного dry-run и `--yes`. CLI повторно вычисляет план и сверяет его с отпечатком; backend внутри транзакции сверяет собственные объекты и LUID. При изменении нужен новый предпросмотр. Несколько `--app` разрешены; отсутствие `--app` означает удаление собственных фильтров после подтверждения. `--config FILE` поддерживает JSON `schemaVersion: 1` с массивом `applications` и `vpnInterface.guid`.

`guard status` читает собственные объекты. `guard uninstall --emergency --yes` удаляет собственные фильтры, sublayer и provider без JSON. Кнопка «Проверить запись в WFP» создаёт служебные объекты **без фильтров**, затем удаляет их и перечитывает состояние. Она не проверяет сетевую защиту. Если собственные объекты уже существуют, проверка отклоняется без изменения. Неясный commit и ошибка проверки после commit выводятся отдельно; автоматическое удаление после них не запускается.

## Журналы

Оба CLI пишут JSONL в `logs` рядом со своим EXE. Для каждого запуска создаётся отдельный файл с UTC временем, PID и `runId`; закрытый файл получает суффикс `.done.jsonl`. `--log-dir` и `--log-level info|debug` переопределяют каталог и уровень. Если основной каталог недоступен, используется `%LOCALAPPDATA%\KillSwitch\logs`; предупреждение идёт в stderr, а stdout JSON остаётся отдельным. В JSON `guard status` есть фактический `logDir`. UI передаёт `operationId` в guard; probe использует свой ID маркеров как `runId`. По умолчанию предел одного файла 10 MiB, общий бюджет компонента 100 MiB, хранение закрытых файлов 7 дней. Значения задаются `KS_LOG_MAX_MIB`, `KS_LOG_BUDGET_MIB`, `KS_LOG_RETENTION_DAYS`. При переполнении активными файлами запись прекращается без удаления файлов других процессов; ошибка журнала не меняет исход WFP-команды.

В журнал попадают пути выбранных EXE, GUID/LUID, собственные WFP-ключи, коды ошибок и адрес явно заданной тестовой цели. Не попадают окружение целиком, конфиг целиком, cookies, ответы HTTPS и сетевые payload. В журнале probe записываются номер попытки, длительность, HTTP статус или ошибка, размер прочитанного ответа и доступные адреса сокета. Успешный HTTP-ответ не доказывает путь через VPN.

## Ограничения

Для probe подтверждены установка WFP, проверка записи WFP, интерфейс, функциональный цикл VPN, работа без GUI, изоляция контрольного EXE и сохранение после перезагрузки. Удаление установленной политики, аварийное восстановление, DNS/прокси, дочерние процессы и отсутствие любых утечек пакетов остаются за пределами базовой проверки. Подробности — [результаты проверок](docs/verification.md), [ручной сценарий](docs/manual-host-test.md) и [расширенный протокол](docs/test-protocol.md).
